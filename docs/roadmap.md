# Идеи на будущее

Здесь собраны функции, которые пока не вошли ни в один план. Реализованное сюда не попадает.

## Принятые решения

- Основа: ONNX Runtime на CPU с моделью E5-small. Работает на любой машине.
- Необязательно: EmbeddingGemma 2 на NPU AMD через Taconite. Ищет заметно лучше (см. `docs/benchmarks/2026-11-gemma-vs-e5.md`), но медленнее на индексации и нужна локальная сборка порта.
- FastFlowLM не подходит по ограничениям (см. `docs/research/2026-11-npu-runtime.md`).
- OCR остаётся для точного поиска по тексту на картинках. Векторы картинок от Gemma его дополняют: они ищут по общему виду ("окно терминала"), а не по надписям (см. раздел про картинки в `docs/benchmarks/2026-11-gemma-vs-e5.md`).
- Только текст и картинки. Аудио и видео не индексируются (решение от 2026-11-04).

## Устройства GPU и NPU для эмбеддингов

Поле `EmbeddingDevice` есть в конфиге. Работают CPU (E5) и NPU AMD (Gemma 2, текст и картинки). Не сделано:

- GPU через DirectML (CUDA необязательно);
- NPU Intel через OpenVINO. Проверить на этой машине нельзя, нужен компьютер с Intel NPU;
- E5 на NPU AMD (Ryzen AI SDK или портирование через IRON);
- форматы картинок WEBP, BMP, GIF, TIFF и HEIC для векторов не читаются (у них остаётся только OCR);
- режим питания NPU Turbo (`xrt-smi configure --pmode turbo`) даёт ещё 4-12% по замерам автора порта. Это настройка системы, агент её не меняет.

Перед включением нового устройства проверить совместимость векторов (косинус не ниже 0.999).

## Поиск на очень больших индексах

Сделано: кэш векторов в памяти, поиск по FTS без лишних соединений, быстрый путь для коротких запросов (см. `docs/benchmarks/2026-11-search-at-scale.md`). Осталось:

- имена файлов ищутся перебором всех путей (около 0.5 мкс на файл); при миллионе файлов нужен индекс по нижнему регистру пути;
- слово из каждого документа всё ещё сортируется по bm25 целиком (около 5 мкс на совпадение);
- замеры сделаны на 20 тысячах файлов, на сотнях тысяч они не проверялись.
