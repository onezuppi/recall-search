# Plan 1 benchmark, 2026-11-03

Measured on the developer machine only. These numbers describe this machine and these folders, not a general result.

Command: `Recall.Agent --once --db <scratch db> --root ...` with roots `C:\projects`, the user's Documents folder
(OneDrive redirected), the Downloads folder and `C:\odata`. Release build. Stage times are summed busy time across
workers, except Scan, which is wall time of a single thread.

## Pass 1 (empty index) - extract and OCR figures are NOT valid

| Item | Value |
|---|---|
| Files listed (indexable types) | 205,974 |
| Wall time | 1 h 23 min 55 s |
| Scan | 22 min 51 s |
| Hash | 24 min 54 s |
| Extract (busy time) | 15 min 47 s |
| OCR of embedded images | 21 s |
| Stored as ok | 70,250 (20,261 extracted, 49,989 deduped by hash) |
| Stored as failed | 135,724 |

Invalid part: 135,377 of the failures were `Another RecognizeAsync operation is already running`. The OCR engine
rejects overlapping calls and the runner used one engine from several workers. Fixed in commit "pool OCR engines"
(test `Concurrent_calls_on_one_instance_all_succeed`). Because almost every image failed at once, Extract, OCR and wall
time of this pass say nothing about real OCR cost. Scan and Hash figures are valid.

Other failures: 314 Office files that the OpenXML SDK rejects (`'' is an invalid xml:space value`), 26 unreadable
images, 5 corrupt Office files, 2 encrypted Office files.
